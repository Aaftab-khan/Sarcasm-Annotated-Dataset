# BBiC: BERT–BiLSTM–CRF Sarcasm Span Extraction

This repository implements a span-extraction pipeline using fast BERT WordPiece tokenization, saved BIO supervision for annotated sarcastic tweets, all-`O` supervision for non-sarcastic tweets, a fine-tuned BERT encoder, a bidirectional LSTM, token emission scores, and a constrained linear-chain CRF trained by negative log-likelihood and decoded with Viterbi.

The repository includes the combined train/test CSVs and the original supplied annotation workbooks/source CSVs used by the data-integrity tests. Existing positive annotation values are not regenerated by the code.

### Use of the newly supplied workbooks and annotation preservation

The workbooks in `data/source/TrainAnnotatedSpansBIO.xlsx` and `data/source/TestAnnotatedSpansBIO.xlsx` are byte-for-byte copies of the latest supplied files. They are the source of truth for row order, labels, preprocessed text, spans, character offsets, and BIO labels. Their original header `Proprocessed Tweet` is standardized to `Preprocessed Tweet` **in the model-ready CSV only**; the workbook itself is not edited.

The supplied training workbook contains 3,468 data rows, including one blank-text non-sarcastic row. That unusable row remains in the source workbook but is excluded from the model-ready training CSV, leaving 3,467 rows (867 sarcastic and 2,600 non-sarcastic). The supplied test workbook contains 1,400 usable rows (200 sarcastic and 1,200 non-sarcastic). The processed CSVs retain the uploaded workbook's row order; in particular, negative examples are not reordered according to the older source CSVs.

Some raw `tweet` cells contain reversible UTF-8/CP1252 encoding corruption (for example, `â€™` for a curly apostrophe or garbled emoji text). The build script repairs only that raw field: positive raw text is restored from the corresponding original raw source row after an alignment check, and negative raw text is decoded in place with the uploaded workbook's order preserved. Irrecoverable replacement characters (`�`) are not guessed or replaced. The following saved gold fields were checked for exact value preservation on every retained row: `sarcastic`, `Preprocessed Tweet`, `Sarcastic Span`, `Character Span`, and `BIO Label Sequence`. Character offsets remain tied to the original `Preprocessed Tweet`; the build does not recalculate offsets, spans, or BIO labels.

To rebuild the model-ready CSVs from the supplied workbook copies, run `python repair_dataset_merge.py` from the project directory. The script stops if the text cannot be aligned to the original source collection or if a protected annotation field would change.

## Model architecture

```text
Tweet text
   │
   ├── Existing Preprocessed Tweet for annotated sarcastic examples
   └── Conservative preprocessing for raw non-sarcastic examples
   │
BERT WordPiece tokenizer (maximum sequence length 128; [CLS]/[SEP] retained)
   │
BERT-base contextual encoder (768-dimensional hidden states)
   │
Dropout (0.30)
   │
Bidirectional LSTM (256 hidden units per direction)
   │
Dropout (0.30)
   │
Linear token-emission layer (O, B-SARC, I-SARC)
   │
Constrained linear-chain CRF (negative log-likelihood training)
   │
Viterbi decoding
   │
BIO sequence → character-level predicted spans
```

The CRF disallows `I-SARC` at sequence start and disallows `I-SARC` after `O`. Token metrics ignore special tokens and padding. Predicted character spans use the fast tokenizer's offsets, not whitespace-based token guessing.

## Important parameter choices

The defaults in `config.yaml` follow the paper's reported setup except for the batch size clarified by the researcher:

| Parameter | Project setting | Status |
|---|---:|---|
| Base encoder | `bert-base-uncased` | Explicit implementation choice. |
| Maximum length | 128 | Reported in paper |
| BERT hidden size | 768 | BERT-base representation size reported in paper |
| BiLSTM hidden units | 256 per direction | Reported hidden-unit setting; output size is 512 after concatenation |
| Dropout | 0.30 | Reported in paper |
| Optimizer | AdamW | Reported in paper |
| Learning rate | `2e-5` | Reported in paper |
| Weight decay | 0.01 | Reported in paper |
| Batch size | **32** | Confirmed configuration for this project. |
| Maximum epochs | 50 | Reported in paper |
| Scheduler | Linear warmup then linear decay | Schedule type is specified; `warmup_ratio=0.10` is an operational default |
| Validation fraction | 0.10 from the official training split | Operational default for holding out validation data from training only |
| Early-stop patience | 5 epochs | Operational default for validation-loss early stopping |
| Seed | 42 | Explicit reproducibility setting; not reported in the paper |
| Gradient clipping | 1.0 | Explicit stability setting; not reported in the paper |

The warmup ratio (`0.10`), validation fraction (`0.10`), early-stopping patience (`5`), seed (`42`), and gradient-clipping norm (`1.0`) are explicit operational defaults chosen to make the runs repeatable. They are not fixed properties of the BBiC architecture. Their effective values are saved in each run's `run_config.json`; report the values actually used for an experiment.

## Non-sarcastic row handling

In the **annotation spreadsheet**, the `Preprocessed Tweet`, `Sarcastic Span`, `Character Span`, and `BIO Label Sequence` cells are left blank for appended non-sarcastic rows. The dataset loader derives all-`O` labels at runtime for the actual tokenized sequence, including the tokenizer special tokens. It does not fill in synthetic annotation strings in the spreadsheets.

For sarcastic examples, the loader uses the existing `Preprocessed Tweet` and saved `BIO Label Sequence` without changing either. It validates that the BIO sequence length equals the real full WordPiece sequence length. If there is a mismatch, it stops with a diagnostic message rather than silently recalculating labels from character spans.

The raw non-sarcastic tweets have blank processed text in the spreadsheet. At runtime, `preprocess_tweet` conservatively removes URLs and user mentions, decodes HTML entities, normalizes excessive repeated letters, standardizes whitespace, and preserves hashtags, emojis, and punctuation. These steps form the explicit preprocessing implementation used for non-sarcastic examples. Annotated positive rows are **not re-normalized** because doing so could invalidate saved offsets and labels.

## 1. Audit the supplied data

Run the structural audit first:

```bash
python audit_data.py
```

This validates the expected class counts, non-empty tweet texts, character offset ranges, span substring consistency (case-insensitive), BIO tag syntax/transitions, and blank span fields for non-sarcastic rows.

Then run the full WordPiece alignment check:

```bash
python audit_data.py --check-tokenizer --model-name bert-base-uncased
```

The tokenizer check is critical: every saved positive BIO sequence must have exactly the same length as the complete WordPiece sequence including `[CLS]` and `[SEP]`. If any examples fail, **do not train and do not automatically rewrite the saved annotations**. Investigate whether the annotation BIO strings were generated with a different tokenizer version or preprocessed string.

The structural audit records two training annotations where the text fragment selected by the existing character offsets differs from the existing `Sarcastic Span` only by letter case. They have not been edited. Character offsets remain in range and their case-folded strings match.

## 2. Train BBiC

Run from the project directory:

```bash
python train.py --config config.yaml --variant bbic --batch-size 32
```

The script creates a deterministic, stratified 90/10 train/validation split **from the official training split only**. The fixed test split is never used for early stopping. It trains up to 50 epochs, selects the checkpoint with the lowest validation loss, and stops after five consecutive non-improving epochs.

Artifacts are written to `outputs/bbic/`:

- `best_checkpoint.pt`: selected trained weights and run metadata
- `run_config.json`: configuration and data counts
- `train_validation_split.csv`: exact source row indices assigned to train/validation
- `training_history.csv`: epoch-wise losses and learning rates
- `loss_curve.png`: training/validation loss plot
- `tokenizer/` and `encoder_config/`: local tokenizer/config assets for checkpoint restoration
- `training_summary.json`: selected epoch and best validation loss

To run on CPU explicitly, add `--device cpu`. To select a GPU, use `--device cuda` or `--device cuda:0`. Batch size is 32 by default; if the actual GPU runs out of memory, reduce it deliberately and record the setting in the run configuration.

## 3. Evaluate on the held-out test split

```bash
python evaluate.py --checkpoint outputs/bbic/best_checkpoint.pt
```

The script writes `outputs/bbic/test_evaluation/` with:

- `metrics.json`: content-token precision/recall/F1, token accuracy, macro-F1, per-tag scores, exact-match span F1, overlap-based partial-match span F1, and an explicitly separate tweet-level presence metric
- `test_predictions.csv`: raw text, model text, gold/predicted BIO sequences, original annotation fields, and predicted character spans
- `token_confusion_matrix.png`
- `token_roc_curve.png` and `token_pr_curve.png`
- `token_curve_metrics.json`

For BBiC and the CRF ablation, the ROC/PR curves use forward-backward CRF marginal probabilities, with `P(B-SARC) + P(I-SARC)` as the sarcasm-token score. Ablations without a CRF use independent token-softmax probabilities. The output JSON records which probability definition was used. ROC-AUC and average precision are computed from predictions on the selected evaluation split, not hard-coded.

### Metric definitions

- **Token sarcasm precision/recall/F1:** `B-SARC` and `I-SARC` jointly form the positive class; special tokens and padding are excluded.
- **Exact-match span F1:** a predicted token-index span must match a gold span exactly within the same tweet.
- **Partial-match span F1:** one-to-one maximum matching; a predicted span matches a gold span if they share at least one token. This is made explicit in the output and may not equal an alternative partial-match convention used by another paper.
- **Tweet-presence metrics:** a separate auxiliary classification view where a tweet is predicted sarcastic if at least one content token is predicted as `B-SARC` or `I-SARC`. Do not conflate this with span-level extraction metrics.

## 4. Ablation runs

The four implemented variants correspond to the architectural components in the paper's ablation table:

- `bert_only`: BERT + linear emission layer, independent token cross-entropy
- `bert_bilstm`: BERT + BiLSTM + linear emission layer, independent token cross-entropy
- `bert_crf`: BERT + linear emission layer + CRF
- `bbic`: BERT + BiLSTM + linear emission layer + CRF

Run the complete sweep with the same split seed and batch size:

```bash
python run_ablation.py --config config.yaml --batch-size 32
```

For a short software smoke run only (not for reported paper results), use `--epochs 1`.

Do not copy the paper's existing result numbers into outputs. The reported ablation metrics must be regenerated from model checkpoints and predictions produced by these commands.

## 5. Single-tweet span extraction

After training:

```bash
python predict.py --checkpoint outputs/bbic/best_checkpoint.pt --text "Thanks for the update #blessed"
```

The output contains the preprocessed text, predicted BIO sequence, and character offsets/text of predicted sarcasm spans. Predictions are model outputs, not ground-truth annotations.

Run the offline/unit/data-integrity tests:

python -m unittest discover -s tests -v

Tests cover CRF likelihood/backpropagation, constrained Viterbi paths, padding masks, tokenizer-length mismatch failures, truncation and `[SEP]` retention, all-`O` labels for non-sarcastic rows, span metric definitions, expected split counts, exact preservation of all original annotated rows, non-sarcastic source order, and blank annotation fields for negatives.

## Experimental reproducibility caveats

1. No performance values are promised by code review alone. The reported scores must be reproduced on the actual model run.
2. This environment did not have Hugging Face Transformers installed and could not reach package/model downloads. Unit tests and structural dataset QA can be run here, but the full pretrained BERT alignment check and end-to-end model training/evaluation must be executed in your Python environment with Transformers and the model weights installed.
3. The choice `bert-base-uncased`, warmup ratio, validation fraction, early-stop patience, seed, and gradient-clipping norm are explicitly configured defaults where the available experimental description does not specify exact values. Keep these settings consistent with the actual run configuration.
4. Batch size is set to **32**, as confirmed for this project. The saved run configuration records the setting used for each experiment.
